Hidden Reliability Failures in Malware Detection

When near-perfect aggregate calibration conceals severe family-level failures.

TL;DR

The released EMBER2024 LightGBM malware detector looks extremely reliable in aggregate: across 1.08 million Windows PE files, it achieves 98.0% accuracy, 0.998 AUC, and an Expected Calibration Error of just 0.0031.

But aggregate performance hides a very different story. When I evaluated reliability separately across malware families, I found families with dramatically higher calibration error and false-negative rates. For malicord, the detector missed 85.2% of malicious samples and had an ECE of 0.602.

Research Question

Is a malware detector that is well calibrated overall also reliable across individual malware families?

This matters because confidence scores can influence which alerts security analysts investigate. A detector can therefore look highly trustworthy according to aggregate metrics while still giving misleading confidence on specific populations of malware.

Overall Performance

98.0% Accuracy
0.998 AUC
0.015 Brier score
0.0031 Overall ECE

My initial hypothesis was that the released detector would show meaningful global miscalibration.

It did not.

The reliability curve remained close to the ideal diagonal, and the maximum calibration error across confidence bins was approximately 0.028. If the analysis had stopped here, the natural conclusion would have been that the model's confidence scores were highly reliable.

What the Aggregate Metric Hid

I then repeated the reliability analysis separately for malware families with at least 100 labeled samples.

Malware family Samples ECE False-negative rate
malicord 324 0.602 85.2%
lazzzy 358 0.452 62.0%
rugmi 512 0.447 61.7%
offercore 136 0.410 54.4%

The strongest example was malicord. Despite the detector's excellent aggregate performance, it classified approximately 85% of samples from this malicious family as benign.

Family size explained only part of the variation. The correlation between family size and ECE was approximately −0.182, suggesting that smaller families tended somewhat toward higher error but that sample frequency alone did not explain the failures.

Failure Analysis

To investigate the high-error families, I used SHAP to examine how EMBER's static PE features influenced individual predictions.

For some poorly detected families, features such as byte entropy and string statistics did not provide strong evidence pushing predictions toward the malicious class. This suggests that the problem may extend beyond assigning the wrong probability to an otherwise-correct representation: the detector may lack sufficiently discriminative feature evidence for some families.

This is an important distinction. Post-hoc recalibration can adjust confidence estimates, but it cannot necessarily repair a model that fails to recognize the underlying samples.

What Surprised Me

The most interesting part of the project was that my original hypothesis was wrong.

I expected to find obvious global calibration problems. Instead, the aggregate detector looked exceptionally reliable. The useful result emerged only after asking whether that aggregate metric was hiding conditional failures.

That changed the project from a calibration check into a broader question about when aggregate security metrics are sufficient evidence for trusting a system.

Why It Matters

Security teams operate under limited analyst attention. If confidence scores influence which files are investigated, a confidently benign prediction can be especially consequential when it is wrong.

Aggregate calibration therefore does not guarantee that a detector provides equally useful confidence estimates across the malware populations an organization may encounter.

Method

I evaluated the publicly released EMBER2024 PE LightGBM benchmark model without retraining it.

  • 1,080,000 Windows PE test samples
  • 540,000 benign and 540,000 malicious samples
  • 2,568 static features per file
  • 464,734 malicious samples with usable malware-family labels
  • Family analysis restricted to families with at least 100 samples
  • 15 confidence bins for calibration analysis

Metrics included accuracy, AUC, Brier score, Expected Calibration Error, Maximum Calibration Error, false-negative rate, family-conditioned calibration, and SHAP-based feature analysis.

Limitations

Malware-family labels are only available for malicious samples, so the same family-conditioned analysis cannot be performed for benign files.

ECE is also sensitive to subgroup sample size. Restricting the analysis to families with at least 100 samples reduces this problem but does not eliminate it.

Finally, SHAP identifies features associated with model predictions but does not establish that those features caused the observed reliability failures. Additional intervention experiments would be necessary to determine whether recalibration, different features, or different training data actually repair these failures.

Next

I am extending the analysis with uncertainty estimates, family-size controls, and experiments testing whether conventional recalibration actually fixes the populations with the largest reliability failures.
